# Mix to Mobile: что известно и что применяем

Исследовано 2026-10-13. Под «Mixtu Mobile» имеется в виду
[Mix to Mobile, Sound on Digital](https://soundondigital.com/products/mix-to-mobile/).

## Подтверждено разработчиком

- Отправитель AU/VST3/AAX для macOS и VST3/AAX для Windows; приёмники — нативные
  приложения iOS/Android. Несколько устройств и несколько потоков.
- Звук передаётся по локальной сети в lossless-формате. При одинаковых sample rate
  отправителя и устройства конверсии нет; при разных выполняется ресемплинг.
- Mac и iPhone/iPad могут связываться через USB. Это функция их продукта;
  наличие кабеля само по себе не обеспечивает такой режим для браузера MConnect.
- [Официальная поддержка](https://soundondigital.com/support/no-streams-found/)
  прямо называет механизм обнаружения **собственным multicast-протоколом**.
  Не следует называть его просто Bonjour: разработчик лишь сравнивает трафик
  обнаружения с mDNS. При наличии IPv6 он приоритетен, IPv4 используется запасным.
- Качество Wi-Fi, разрешения локальной сети, фильтры и firewall влияют на работу.
- [Начиная с 1.5](https://soundondigital.com/press-release/exciting-new-features-and-improvements-for-mix-to-mobile-v1-5-0-2/)
  доступны отдельные desktop sender/receiver приложения.

## Что не установлено

Открытого репозитория самого Mix to Mobile или пригодного для встраивания SDK
поиск не выявил. Формат аудиопакета, фактический медиа-транспорт, битность,
алгоритм jitter buffer, коррекция потерь и синхронизация часов не описаны в
найденной документации. Утверждать, что там конкретно UDP/PCM/FLAC/RTP, нельзя.
Исходный код продукта в MConnect не копировался, бинарники не декомпилировались.

## Следствия для MConnect

Браузерный вариант обеспечивает передачу внутри LAN, отсутствие voice DSP,
безопасный tap в DAW, sinc SRC, несколько слушателей и автоматический выбор
сетевого интерфейса и буфера. QR даёт адрес конкретного экземпляра и
позволяет обойти необходимость multicast discovery, недоступного обычной странице.

Реализовано автоматическое переподключение после временного сбоя и адаптация
браузерного буфера там, где API это поддерживает. Захват и кодирование не работают
без слушателей; один кодированный поток используется для всех телефонов.
Проверяется декодированный стереосигнал, не только статус подключения.
Для устойчивости используется готовый WebRTC стек из открытого PGStream.

По требованию пользователя отдельное приложение не создаётся. MConnect
принимается обычным браузером с минимумом действий.

**Разница качества остаётся:** WebRTC Opus 320 kbps — сжатие с потерями. Это
не lossless Mix to Mobile. Собственный PCM/FLAC путь через Browser AudioWorklet
потребовал бы secure context; самоподписанный LAN HTTPS добавляет ручную настройку
доверия. Такой путь не включён в версию 0.1.

Доказательств равной или меньшей задержки относительно Mix to Mobile пока нет:
нужны измерения обоих продуктов на одинаковом телефоне/сети/аудиовыходе.
