# Обновления MConnect

Версия 0.1.3 добавляет строку обновлений под индикаторами, сохраняя текущий
интерфейс. При открытом окне плагин проверяет стабильный релиз GitHub не чаще
раза в сутки. Нажатие на строку версии запускает ручную проверку.
Если есть новая версия, появляется `Update … available · Download`.
После скачивания строка меняется на `Open installer`.

Перед продолжением установки сохраните проект и закройте DAW. Установка
выполняется обычным macOS Installer, новая версия загружается при следующем
запуске DAW. Текущий аудиосигнал и состояние проекта обновление не меняет.
Автоматическая часть — проверка и обнаружение релиза; скачивание запускается
кнопкой, установка подтверждается пользователем.

0.1.2 и более ранние версии нужно один раз обновить установщиком до 0.1.3.
В них механизма проверки обновлений ещё нет.

## Публикация

Публичный репозиторий: [ibotpafos/MConnect](https://github.com/ibotpafos/MConnect).
[Релиз 0.1.3](https://github.com/ibotpafos/MConnect/releases/tag/v0.1.3) опубликован.
После публикации проверены настоящий HTTPS-запрос и разбор метаданных релиза
самим клиентом, а также загрузка опубликованного `.pkg` с совпадением SHA-256.
Уведомления появятся при публикации следующих стабильных версий.

1. Измените `project(MConnect VERSION …)` и добавьте запись в `CHANGELOG.md`.
2. Соберите universal AU/VST3, выполните тесты и создайте пакет:

   ```sh
   bash scripts/build.sh
   python3 scripts/package_macos.py build
   python3 scripts/release_github.py
   ```

3. Последняя команда проверяет пакет и SHA-256 и показывает точные файлы,
   репозиторий, тег и текст релиза. Она работает локально.
4. После проверки содержимого подготовьте публичный репозиторий и черновик:

   ```sh
   python3 scripts/release_github.py --upload-draft --create-repository
   ```

5. Для публикации проверенного релиза:

   ```sh
   python3 scripts/release_github.py --publish
   ```

Скрипт отправляет только чистую ветку `main`, проверяет совпадение `origin`
со встроенным адресом, создаёт неизменяемый тег `vX.Y.Z`, загружает `.pkg`,
ручной ZIP, соответствующие исходники и SHA-256. Он сверяет digest каждого
загруженного файла с GitHub перед публикацией. Существующий опубликованный
релиз не перезаписывает. Для первого запуска можно совместить `--publish`
с `--create-repository`, когда создание публичного репозитория согласовано.

Для следующих публикаций используйте скрипт из актуальной ветки `main`:
он находит черновики через список релизов и проверяет/публикует по числовому ID.
У черновика временный адрес `untagged-*`, а endpoint по публичному тегу может
возвращать 404. Архив исходников установленного 0.1.3 соответствует его
неизменяемому тегу `v0.1.3`; исправление инструмента публикации находится в `main`.

Для другого репозитория измените default `MCONNECT_UPDATE_REPOSITORY` в CMake
и соберите новую установочную версию; пользователи уже выпущенной версии
продолжают проверять встроенный в неё адрес.

## Устройство и ограничения

- Проверка создаётся только редактором, `SharedResourcePointer` объединяет её
  между экземплярами одного процесса. Закрытие последнего окна отменяет
  сетевую операцию и дожидается выхода её обработчиков. Аудиопоток и обработчик
  `processBlock` к обновлениям не обращаются.
- Низкоприоритетный рабочий поток существует только на время операции.
  Суточный кеш и блокировка между процессами уменьшают число запросов;
  после ошибки следующая автоматическая попытка — через 30 минут.
- Проверяется `/repos/ibotpafos/MConnect/releases/latest`, без токена GitHub.
  Данные не содержат звука, имени проекта, pairing key или сведений о DAW.
  GitHub видит обычный HTTPS-запрос и IP-адрес компьютера.
- Проверяются стабильная числовая версия, `draft`/`prerelease`, точные
  репозиторий, тег, имя universal `.pkg`, HTTPS URL, размер и digest SHA-256.
  Размер JSON ограничен 256 KiB, вложенность — 32; установщик — 128 MiB.
  Проверка digest обнаруживает повреждённый/подменённый файл относительно
  доверенных метаданных GitHub. Она не заменяет Developer ID или нотарификацию.
- Системный `URLSession` использует временную сессию без cookies/credentials,
  системную проверку TLS, ограниченные таймауты и отмену операции. Установщик
  сначала хранится под временным именем и становится доступен после проверки
  размера и SHA-256. Пакет повторно проверяется рабочим потоком перед открытием
  Installer; удалённый или изменённый файл скачивается заново.
- Пакеты находятся в `~/Library/Caches/MConnect/Updates/`. Их можно удалить
  при закрытом окне плагина. При офлайне известное уведомление сохраняется.
- В 0.1.3 установка рассчитана на macOS AU/VST3. Нет отдельного обновляющего
  приложения, демона или скрытой установки во время работы DAW.

## Выбор решения

Рассмотрены [Sparkle](https://sparkle-project.org/) и
[JUCE Plugin Starter](https://github.com/danielraffel/JUCE-Plugin-Starter).
Sparkle поддерживает bundle-плагины, но его `.pkg`-обновления всё равно
требуют авторизации пользователя и добавляют framework/helper-компоненты.
Текущему небольшому плагину достаточно JUCE для версий/кеша/интерфейса,
SHA-256 из модуля JUCE и системного транспорта Foundation. Новая внешняя
библиотека не добавляется.

Источники: [GitHub stable releases](https://docs.github.com/en/rest/releases/releases#get-the-latest-release),
[GitHub asset digest](https://docs.github.com/en/rest/releases/assets),
[Sparkle package updates](https://sparkle-project.org/documentation/package-updates/),
[JUCE SharedResourcePointer](https://docs.juce.com/master/classjuce_1_1SharedResourcePointer.html),
[Apple URLSession cancellation](https://developer.apple.com/documentation/foundation/urlsession/invalidateandcancel()).
