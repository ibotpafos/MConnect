# Проверка MConnect 0.1.2

Дата: 14 октября 2026 года. Стенд: macOS 26.6.2, Apple Silicon, Mac16,7.
DAW не запускалась. Используются программный источник, валидаторы AU/VST3
и реальные Chromium/WebKit. Отчёт прежней версии: [VALIDATION_0.1.1.md](VALIDATION_0.1.1.md).

## Что исправлено

- Точное восстановление дробного нормализованного Stream после сохранения состояния;
  тип boolean и старые пресеты сохранены.
- Конкурентная инициализация AES и общие self-test счётчики Mbed TLS:
  неизменяемые таблицы, предварительная инициализация и штатная POSIX-синхронизация.
- Конкурентный stop flag CivetWeb: атомарный helper в генерируемой копии зависимости.
- WebRTC привязан к выбранному LAN-интерфейсу, чтобы локальный звук не шёл через VPN.
- Сброс и установка stored callbacks libdatachannel защищены существующим mutex;
  параллельные reset/call проверяются отдельной регрессией.
- Автоматический буфер увеличивается при потерях/concealment даже при малом джиттере;
  после восстановления задержка снова постепенно снижается.

Подробности и основания: [STABILITY.md](STABILITY.md). Подавлений санитайзеров нет.

Native core проверяет bit-exact float/double passthrough, bypass/offline, mono,
нулевую добавленную задержку в тракте DAW, сохранение/загрузку состояния и старый
формат пресетов, конкурентный FIFO/overflow, стерео SRC/антиалиасинг и предельные
параметры хоста. Browser matrix проверяет раздельные декодированные тоны 997 Hz L
и 1499 Hz R, autoplay fallback, автоматический и ручной reconnect.

Регрессия callbacks выполняет 8000 сбросов из двух потоков параллельно 4000
вызовам, затем проверяет пропущенное событие и очистку устаревшего события.
Исходный race report сохранён в `tsan-lan-server.log`.

Санитайзерами охвачены C, C++ и Objective-C++ модули, включая macOS-код JUCE.
Частичная настройка только C/C++ не использована как итоговое доказательство:
она не наблюдала синхронизацию macOS thread lifecycle. ASan запускается с
`detect_leaks=0`: полноценная проверка утечек LeakSanitizer не заявляется.
Длительный тест отдельно измеряет RSS после прогрева.

TSan существенно замедляет код, поэтому его профиль проверяет конкурентную
безопасность без замеров тона во время live смены частоты (`decodedAudioChecked:false`).
Release и ASan/UBSan сохраняют проверки декодированного стерео. Browser/CPU suites
выполняются последовательно; параллельная компиляция или другой источник могут
искажать тайминги и занимать порт временно выключенного тестового сервера.

В регрессии буфера подменяется только getStats, RTP/приёмник остаются настоящими.
Проверяется реакция на потери при нулевом джиттере, затем на concealment без новых
потерь и снижение после здорового интервала. Длительный тест использует настоящую
статистику без подмены; сохраняет все три окна каждого замера, потери и target.
Краткие просадки видны в JSON. Это не доказательство отсутствия сетевых артефактов.

## Производительность

| Частота источника | Базовый / активный CPU одного ядра, % | Добавочный CPU | RSS процесса | Буфер браузера за окно | Пакеты / потери за окно |
| --- | --- | --- | --- | --- | --- |
| 48 kHz | 0.83 / 2.50 | 1.67% | 66.4 MiB | 48.7 ms | 607 / 0 |
| 192 kHz | 0.83 / 3.66 | 2.83% | 57.6 MiB | 39.8 ms | 604 / 0 |

В обоих окнах intervalConcealed = 0, encode/conversionErrors = 0. Выбранный
remote candidate совпадает с LAN-адресом QR; RTT округляется до 0 ms на этом
локальном стенде. Это не обещание нулевого RTT по реальному Wi-Fi.

До исправления bindAddress один из прогонов выбрал utun/VPN candidate с RTT
326 ms и потерял 67 пакетов за окно при 536 полученных. Ранее были также
неустойчивые headless-замеры с большим фактическим буфером и один провал
порога 500 пакетов за окно; эти логи сохранены, а не зачтены как успешные.
Итоговый benchmark проверяет выбранный маршрут и не более 1% потерь за окно.

Прогрев браузера — 8 s. Как в проверке декодирования, в отдельном тестовом
браузере работает тихий Web Audio graph. Он помогает держать headless аудиочасы
активными, не включён в страницу телефона и не входит в измеряемый процесс
плагина. Настройка стенда изменялась, поэтому строгий числовой вывод об ускорении
по сравнению с 0.1.1 не делается. CPU зависит от частоты источника и текущей
нагрузки компьютера; это два коротких измерения, а не полный профиль DAW.


100% CPU соответствует одному ядру. Базовый и активный интервалы — по 6 s после
прогрева; браузер работает отдельно. RSS включает JUCE-хост, генератор и сеть,
а не только плагин. Проверяются сотни RTP-пакетов и декодированная энергия.
Буфер по интервальной разности jitterBufferDelay/emittedCount — **не полная
акустическая задержка DAW → телефон**. Размер блока, устройство вывода, сеть
и Bluetooth добавляют задержку; браузер может увеличить буфер сверх подсказки.

Без слушателей аудиоколбэк не копирует звук и кодер не работает. При закрытом
редакторе индикаторы не рассчитываются. Кодер общий для всех слушателей;
фиксированный FIFO — 512 KiB. Исправления не добавляют работу в аудиоколбэк.

## Установщик

`dist/MConnect-0.1.2-macos-universal.pkg`: AU и VST3, macOS 11+, arm64 + x86_64.
Установка для текущего пользователя, без установочных скриптов. Лицензии,
документация и исходники находятся в `~/Library/Application Support/MConnect/`.
Архив исходников проверяется на совпадение с репозиторием и обоими бинарниками.
AU, VST3 и документы имеют отдельные receipts. При обновлении пакеты заменяются
целиком; старые `.backup-*` от ручного скрипта сохраняются.

Плагины подписаны ad-hoc; у .pkg нет Developer ID Installer и нотарификации.
Gatekeeper на чужом Mac и GUI-проход Installer здесь не проверены. Порядок
установки и ручного разрешения: [INSTALL.md](INSTALL.md).

## Особенности стенда и границы

- Тестовый источник удерживает macOS activity для программного аудио. Hidden
  браузеры используют тестовый `MConnectBrowserTiming` через DYLD/XPC injection,
  чтобы аудиочасы не тормозились из-за фонового состояния. Модуль не включён
  в поставку и не изменяет обычные браузеры или системные настройки.
- Пользователь подтвердил звук на физическом iPhone в 0.1.0. Физическая матрица
  Android/iPhone и DAW для 0.1.2 не проводилась; desktop Chromium/WebKit её не заменяют.
- Rosetta проверяет x86_64 на этом Apple Silicon Mac, а не на отдельном Intel Mac.
- Windows/Linux бинарники не собирались. Pro Tools AAX требует отдельного SDK.
- Нужна доступная локальная сеть. Браузер может требовать одно нажатие «Слушать»;
  фон и блокировка экрана управляются ОС телефона. Opus 320 kbps — сжатие с потерями.

## Повторение

```sh
ctest --test-dir build -C Release --output-on-failure
arch -x86_64 build/MConnectTests_artefacts/Release/MConnectTests
auval -v aufx Mcnt Mcnn
arch -x86_64 /usr/bin/auval -v aufx Mcnt Mcnn
MCONNECT_TEST_TIMING_LIBRARY="$PWD/build/libMConnectBrowserTiming.dylib" \
MCONNECT_PLAYWRIGHT=/absolute/path/to/node_modules/playwright \
python3 tests/run_receivers.py
MCONNECT_TEST_TIMING_LIBRARY="$PWD/build/libMConnectBrowserTiming.dylib" \
MCONNECT_PLAYWRIGHT=/absolute/path/to/node_modules/playwright \
node tests/robustness.cjs
MCONNECT_SOAK_SECONDS=600 \
MCONNECT_TEST_TIMING_LIBRARY="$PWD/build/libMConnectBrowserTiming.dylib" \
MCONNECT_PLAYWRIGHT=/absolute/path/to/node_modules/playwright \
node tests/soak.cjs
```

Для санитайзеров используются отдельные arm64 build directories с
RelWithDebInfo. ASan/UBSan: `-fsanitize=address,undefined -fno-omit-frame-pointer
-fno-sanitize-recover=all`; TSan: `-fsanitize=thread -fno-omit-frame-pointer`.
Передайте соответствующие флаги во **все** CMAKE_C_FLAGS, CMAKE_CXX_FLAGS,
CMAKE_OBJCXX_FLAGS и linker flags, затем соберите MConnectTests/MConnectHarness.
Укажите MCONNECT_TEST_HOST и MCONNECT_TEST_HOST_LOG для браузерного цикла;
только для TSan добавьте MCONNECT_TEST_RACE_ONLY=1.

ПО для испытаний не является runtime-зависимостью плагина.
